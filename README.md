# IleraPoint

A voice-led, code-switching patient intake and triage kiosk for primary-care settings. V3 adds real Tencent PalmAI patient identification, consented consultation recording, Supabase persistence, and an authenticated doctor review and prescribing workspace.

## Run locally

```bash
npm install
cp .env.example .env
npm run dev
```

Add the Sahara, Gemini, Tencent PalmAI, and Supabase values listed in `.env.example`, then open `http://localhost:5173`. Sahara, Gemini, and Tencent are real integrations; there are no mock providers. If Sahara TTS stalls, FFmpeg's local device voice returns a WAV so intake can continue. Typed answers remain available as an accessibility fallback, but still use Gemini for extraction.

The server runs on port `8787`; Vite proxies `/api` requests to it. API keys are read only by the server and are never exposed to browser code.

## Yoruba image to speech

Open `http://localhost:5173/yoruba-image-to-speech` directly; this public utility does not require patient or doctor authentication. Upload a JPG, PNG, or WebP image up to 8 MB. Gemini first transcribes the page, then a higher-quality screenplay pass restores Yoruba tone marks, underdots, joined words, and punctuation without translating English code-switching or rewriting dialogue. Review the result, choose a male or female Sahara voice for every detected character, then generate, preview, and download a WAV using Sahara v2.5's Yoruba/English code-switching voice. Character headings are not spoken; dialogue is generated by voice in parallel and restored to screenplay order with explicit silence for line breaks and punctuation. This route requires Sahara to succeed and does not substitute the kiosk's local fallback voice. Document speech uses a separate 90-second request deadline while leaving the low-latency kiosk speech deadline unchanged.

## V2 interview behavior

- The interview ends naturally when `still_missing` is empty, as early as turn two.
- Seven turns is the hard safety ceiling, not the normal target.
- Gemini receives every question and raw transcript from the current visit.
- A correction in a later answer replaces conflicting record values instead of appending duplicates.
- “Redo my last answer” restores the exact pre-turn record snapshot and re-asks the same question without a model call.
- The patient can edit every patient-facing record field before clinician review.

## V3 patient flow

- `Tap to begin` opens camera-based palm identification.
- Returning patients use Tencent 1:N RGB palm search; new patients register name/phone and bind the Tencent palm ID to their Supabase UUID.
- Tencent 1:1 compare is exposed at `POST /api/palm/compare` for explicit verification workflows.
- Manual name/phone lookup remains available whenever palm capture or matching fails.
- New patients choose a dedicated registration path, enter name and phone first, then enroll their palm before the conversation begins.
- MediaPipe traces one open hand locally and gates automatic capture until the full palm is centered, open, and stable. Matching PayByPalm's proven kiosk path, the camera requests 1280×720 and sends the sharpest non-empty full-resolution frame from a three-shot burst to Tencent; landmarks are guidance only and do not crop the provider image. Its WASM runtime and hand model are self-hosted under `public/mediapipe`.
- A separate consent screen explains full-session video, private clinician access, and the right to continue without video.
- Accepted consent starts one modest 640×480 stream used by both per-turn audio recording and continuous audio/video recording. A persistent red indicator remains visible throughout recording.
- On completion, the corrected record, complete turn history, consent choice, red-flag state, and any recording are saved. Video objects are private and only delivered through short-lived signed URLs.
- Emergency flow: say or type `I have chest pain` to trigger the deterministic safety screen immediately after Gemini updates the record.

## Doctor workspace

- `/doctor/login` — Supabase email/password authentication.
- `/doctor/queue` — oldest-first pending and flagged consultations.
- `/doctor/case/:id` — structured intake, complete transcript, consented video, and approve/flag actions.
- `/doctor/case/:id/prescribe` — the case workspace with the prescription form; submitting marks the consultation complete.

Create the auth user in Supabase Auth, then insert a matching row in `doctors` using the same email.

## Architecture

- `src/lib/providers/SpeechProvider.js`: shared interface and Sahara provider.
- `src/components/YorubaImageSpeechScreen.jsx`: public image upload, editable Yoruba transcription, Sahara playback, and WAV download screen.
- `src/lib/interview/session.js`: full turn history, record snapshots, rollback, and direct record editing.
- `server/index.js`: Sahara sync STT with 503 polling fallback, streaming TTS WebSocket proxy, and one history-aware Gemini structured-output call per turn.
- `server/yorubaOcr.js`: exact Yoruba text extraction from images using Gemini multimodal input.
- `server/yorubaScript.js`: Yoruba orthography restoration, code-switched English preservation, and screenplay cast extraction.
- `server/tencentPalm.js` and `server/routes/palm.js`: in-memory RGB images and server-only Tencent register/search/compare calls.
- `server/routes/consultations.js`: private Storage upload, consultation persistence, doctor queue/case reads, and signed video URLs.
- `server/routes/prescriptions.js`: authenticated prescription writes and completion status.
- `src/lib/media/sessionRecorder.js`: one media stream for per-turn audio clips and consented continuous recording.
- `src/lib/safety/redFlags.js`: deterministic red-flag function, invoked after every interview turn.
- Supabase holds patients, consultations, doctors, and prescriptions. Palm images are never persisted.

## Supabase setup

Run [`supabase/migrations/0001_ilera_v3.sql`](supabase/migrations/0001_ilera_v3.sql) in the Supabase SQL editor or migration CLI. It creates the V3 tables, indexes, status constraints, RLS, and private WebM-only `consultation-videos` bucket with a 50 MB object limit. The Express server uses the service-role key; never place that key in a `VITE_` variable. The browser receives only the project URL and anon key for Supabase Auth.

## Speech playback troubleshooting

Sahara streaming TTS is given 6.5 seconds on the server. If it stalls or disconnects, FFmpeg's local `flite` engine creates the WAV; this is generated speech, not mock API data. After a Sahara failure, a 60-second circuit breaker sends subsequent questions directly to the local voice (typically about 200 ms) instead of repeating the failed wait. The browser has a ten-second overall playback deadline. The server reconnects once only for genuine socket/handshake failures and does not retry stalled generation. The kiosk runtime therefore requires an FFmpeg build with the `flite` filter.

Patient-turn transcription uses Sahara's asynchronous file endpoint with LLM transcript corrections disabled, a one-second provider-safe polling cadence, and a 15-second server deadline. Interview extraction defaults to `gemini-2.5-flash-lite` with thinking disabled and a 10-second server deadline. Server logs and `Server-Timing` headers report each stage separately. Repeated question audio is cached in memory for the lifetime of the API process.

For Raspberry Pi kiosk mode, point Chromium at the Vite/served production URL and launch with `--kiosk` after granting microphone access.
